# Saans wire formats

Two UDP datagram types share the sensor port (default 5566). Both are
little-endian. A receiver tells them apart by the first four bytes.

| Magic | Type | When |
|---|---|---|
| `0xC5110001` | raw CSI | Debug / data collection only (ADR-001) |
| `0x534E4153` (bytes `53 41 4E 53`, "SANS" on the wire) | FeatureFrame v1 | Normal operation |

## 1. raw CSI

See `wifisense/sources/esp32_udp.py` for the
byte-exact reference. 20-byte header, then int8 I/Q pairs, **imaginary
first**. Sequence number at bytes 12..15.

## 2. FeatureFrame v1 — 68 bytes, fixed size

One frame per link (rx node, tx id) every `1 / frame_rate_hz` seconds
(default 2 Hz). Reference implementation: `wifisense/features.py`.

| Offset | Size | Type | Field | Meaning |
|---|---|---|---|---|
| 0 | 4 | u32 | `magic` | `0x534E4153` (ASCII "SANS") |
| 4 | 1 | u8 | `version` | `1` |
| 5 | 1 | u8 | `node_id` | Receiving node |
| 6 | 1 | u8 | `tx_id` | Transmitting node; `0xFF` = an access point / unknown |
| 7 | 1 | u8 | `flags` | See below |
| 8 | 4 | u32 | `seq` | FeatureFrame counter, +1 per frame, wraps |
| 12 | 4 | u32 | `uptime_ms` | Since the extractor started |
| 16 | 2 | u16 | `csi_rate_chz` | Achieved CSI rate over the last 10 s, Hz × 100 |
| 18 | 2 | u16 | `loss_permille` | CSI sequence loss over the last 10 s, ‰ |
| 20 | 4 | f32 | `motion_energy` | Presence-band (0.1–2 Hz) RMS of the fused signal, the presence detector's energy |
| 24 | 4 | f32 | `presence_threshold` | The presence detector's threshold (0 until calibrated) |
| 28 | 4 | f32 | `gross_motion` | RMS over the last 1 s of the fused signal through **two cascaded** 1–4 Hz biquad bandpasses (one section leaks breathing): limbs and walking, not breathing |
| 32 | 4 | f32 | `breath_rms` | 0.1–0.5 Hz band RMS over the last 2 s. **Vitals-gated** |
| 36 | 4 | f32 | `breathing_bpm` | **Vitals-gated** |
| 40 | 4 | f32 | `breathing_conf` | [0, 1]. **Vitals-gated** |
| 44 | 4 | f32 | `heart_bpm` | **Vitals- and heart-gated** |
| 48 | 4 | f32 | `heart_conf` | **Vitals- and heart-gated** |
| 52 | 4 | f32 | `best_bnr` | Highest per-subcarrier breathing-to-noise power ratio in the last selection window (link quality). **0 = unknown**: before the first window, or on a memory-constrained node that does not compute it (its row store is half the per-link state; no detector reads this field) |
| 56 | 4 | u32 | `calib_age_s` | Seconds since presence calibration completed (`0xFFFFFFFF` = not calibrated) |
| 60 | 1 | i8 | `rssi_dbm` | Mean RSSI over the frame interval |
| 61 | 1 | i8 | `noise_floor_dbm` | Mean noise floor (`-128` = unknown) |
| 62 | 1 | u8 | `n_subcarriers` | |
| 63 | 1 | u8 | `reserved` | 0 |
| 64 | 4 | u32 | `crc32` | IEEE 802.3 CRC-32 (zlib) of bytes 0..63 |

### Flags (byte 7)

| Bit | Name | Set when |
|---|---|---|
| 0 | `calibrated` | Presence detector has an empty-room threshold |
| 1 | `occupied` | Presence detector says occupied |
| 2 | `vitals_enabled` | This link's space has opted in to vitals (ADR-005) |
| 3 | `raw_mode` | The node is *also* streaming raw CSI. Must be visible so a dashboard can show it |
| 4 | `breathing_valid` | Breathing status is VALID or DEGRADED and vitals are enabled and the space is occupied |
| 5 | `heart_valid` | Same for heart, and heart is enabled |
| 6 | `discontinuity` | A CSI gap longer than `max_gap`, a reboot or a reset happened since the previous FeatureFrame |
| 7 | — | 0 |

### Gating rule

Every field derived from the breathing or heart band (`breath_rms`,
`breathing_*`, `heart_*`) is **written as 0.0** unless `vitals_enabled`
is set; `heart_*` additionally needs heart enabled. Gating happens on the
node, so a gateway never receives what it is not allowed to hold.

### Timing

- Features are sampled every `round(fs / frame_rate_hz)` CSI frames
  (after gap filling), not by wall clock, so they are deterministic
  given the input.
- `breath_rms` and `gross_motion` are computed over the last 2.0 s and
  1.0 s of filtered samples (`round(fs * window)` samples).
- `csi_rate_chz` and `loss_permille` use arrival timestamps and sequence
  numbers over the last 10 s.

### Why these fields and no others

Each health detector in `SAANS_PLAN.md` §2.1 reads only these fields:
presence and inactivity from `occupied`, `motion_energy`,
`gross_motion`; breathing pause from `breath_rms` and `breathing_conf`;
rate checks and trends from `breathing_bpm`/`conf`; collapse from
`gross_motion` and `occupied`. System health reads `csi_rate_chz`,
`loss_permille`, `calib_age_s`, `best_bnr`, `rssi_dbm`, `noise_floor_dbm`
and the `discontinuity` flag. Nothing here can reconstruct the channel.

## 3. Golden vectors

Generated by `python3 spec/golden/generate.py` from the Python reference
into `spec/golden/`. For each vector set `NAME`:

| File | Used by | Content |
|---|---|---|
| `NAME.kv` | C++ (no JSON parser needed) | One `key value` per line: scalars, then `array.X N` per array |
| `NAME.json` | Rust, tools | The same scalars, plus `{X: [file, N]}` |
| `NAME__X.f64` | both | Array X as raw little-endian float64 |

`.kv` and `.json` carry identical information; neither is more
authoritative. `MANIFEST` lists the sets. Never edit vectors by hand;
regenerate them and say why in the commit.

### What "match" means

- **Codec** (`feature_codec`): encode the given field values and compare
  **bytes exactly**; decode the bytes and compare fields exactly.
- **Stages and end-to-end** (`features_*` and the rest): compare values with
  the tolerances in `SAANS_PLAN.md` §4 (Rust f64: 1e-9 relative; C++
  float32: 1e-4 relative, 0.05 BPM on rates). An independent float32 DSP
  cannot reproduce the reference's f64-then-round-to-f32 bits, so encoded
  `features_*` frames are compared field by field after decoding, not
  byte by byte. Integer fields (`node_id`, `tx_id`, `seq`, `n_subcarriers`,
  `calib_age_s`, `rssi_dbm`, `noise_floor_dbm`) must match exactly;
  `uptime_ms`, `csi_rate_chz` and `loss_permille` within 1. Flags must
  match exactly except within one frame of a transition in the reference,
  where a threshold comparison can legitimately land either side.
